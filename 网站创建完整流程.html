一、项目在哪

分三层，改的时候只需要动第一层。

① 源文件（你要编辑的）

/mnt/Workbench/Midsite

这是唯一的原件。所有页面、配置、样式、资料都在这里。

⚠️ 这块盘是 USB 移动硬盘

/mnt/Workbench 是 /dev/sda4，而 /dev/sda 是一块 Thinkplus 512G USB 移动硬盘。你的系统根目录也在同一块盘的 sda3。

所以：拔盘 = 系统和项目一起消失。备份必须复制到别的物理磁盘，放在同一块盘的其他分区不算备份。

好消息是代码已经推到 GitHub，云端有副本。但 assets/files/ 里没推送过的大文件只在本地。

② 构建产物（自动生成，别手改）

/mnt/Workbench/Midsite/_site/

Jekyll 把 Markdown 编译成 HTML/CSS/JS 后放在这里。每次构建都会整个重写，手改无效。这个目录不会上传到 GitHub。

③ 线上

访问地址https://hanyi04.github.io
实际文件GitHub 服务器 + 全球 CDN 节点（不在你电脑上）

完整链路

二、日常编辑

这一章是你平时最会用到的部分。所有操作都在终端里，三条命令一组。

2.1 加文件（最常用）

把文件放进 assets/files/，然后推送。不用改任何代码，列表自动更新。

cd /mnt/Workbench/Midsite

# ① 把文件拷进目录
cp ~/某份讲义.pdf assets/files/

# ② 登记改动
git add -A
git commit -m "加讲义"

# ③ 推送（会问密码，见 3.2）
git push

也可以三步合成一条：

cd /mnt/Workbench/Midsite && cp ~/讲义.pdf assets/files/ && git add -A && git commit -m "加讲义" && git push

推完等 1～2 分钟，刷新线上页面，文件会同时出现在「下载」和「预览」两页，按修改时间倒序排，新的在最前。

限制数值说明
单文件大小100 MBgit push 硬限制，超了直接推不上去
建议大小< 25 MB再大访客打开会慢
文件名避免空格和 ? * | < >中文可以用，英文+数字+短横线最保险
子目录支持放 assets/files/子目录/ 也会被列出

2.2 改首页文字

首页内容在 _pages/home.md，但名字、身份、单位、邮箱这些在 _config.yml：

name: "HanYi04"                 # 导航栏和页脚显示的名字
title: "一句话身份"              # 首页那句「我是 XXX」
institution: "你的学校或单位"
email: "你的邮箱"
photo: ""                       # 头像文件名，放 assets/images/ 下

改完推送即可。想改首页的段落文字，直接编辑 _pages/home.md（Markdown 语法，**粗体**、- 列表 这样写）。

首页还留着占位符

现在首页写着「一句话身份，例如：物理学研究生」和「你的学校或单位」，这两个是占位文本，记得改成你自己的。

2.3 改配色

当前是黑白灰 + 红，红 #d0021b 是唯一的彩色。

只改主色，动一处：

# _config.yml
accent_color: "#d0021b"

改完整套红（含深色模式）要同时改 _sass/base/_variables.scss：

:root {
  --accent: #d0021b;              /* 亮色模式的主色 */
  --accent-hover: #a80116;
  --accent-light: rgba(208, 2, 27, 0.07);
}

[data-bs-theme="dark"] {
  --accent: #ff4d63;              /* 深色模式下要亮一档 */
  --accent-hover: #ff7186;
}

同一个文件里还有背景色、文字色、边框色、阴影，全部是 CSS 变量，改一处全站生效。

2.4 改导航

导航项由 _config.yml 的 nav_pages 控制：

nav_pages:
  - name: home       # 显示「首页」，链接 /
  - name: files      # 显示「下载」，链接 /files/
  - name: preview    # 显示「预览」，链接 /preview/

不想要哪一项就在行首加 # 注释掉。

中文显示名映射在 _includes/header.html 里（home→首页、files→下载、preview→预览）。想加新导航项，除了 nav_pages 加一行，还要在那个文件里补一段映射。

2.5 加新页面

1

在 _pages/ 下新建 about.md：

---
title: "关于"
layout: gridlay
permalink: /about/
---

## 关于

这里写内容。
2

在 _config.yml 的 nav_pages 里加一行 - name: about，并在 _includes/header.html 里补一段中文名映射。

可用的 layout：gridlay（常规页，带淡入）、homelay（窄栏居中，首页用）、page、post。

之前删掉的页面还在

博客、CV、论文、研究、相册、留言板的模板都归档在 _archive/ 里（下划线开头，Jekyll 不处理）。想恢复就把文件移回 _pages/，再在 nav_pages 加一行。

2.6 删文件

cd /mnt/Workbench/Midsite
rm assets/files/旧文件.pdf
git add -A
git commit -m "删掉旧文件"
git push

推完列表自动少一项。

三、更新与发布

改完任何东西，都是同一个流程：add → commit → push。推上去之后 GitHub 自动构建，1～2 分钟生效。

3.1 三条命令

cd /mnt/Workbench/Midsite
git add -A                        # 把所有改动加入暂存区
git commit -m "说明这次改了什么"    # 做一次提交
git push                          # 推到 GitHub

这三条命令各自在干什么

命令作用类比
git add -A把新增/修改/删除的文件标记为「待提交」把东西装进箱子
git commit给这批改动打一个带说明的快照封箱并贴上标签
git push把这个快照送到 GitHub发货
提交信息怎么写

随便写，自己能看懂就行，比如「加讲义」「改邮箱」「换了配色」。这些信息会留在历史记录里，方便以后回溯。

推送失败了怎么办

项目里带了 ./push.sh，会自动重试 40 次（约 3 分钟），网络一通就推上去：

cd /mnt/Workbench/Midsite
./push.sh

3.2 认证方式

推送需要向 GitHub 证明「你是你」。两种方式，配一次就行。

Token（HTTPS）SSH 密钥
怎么用git push 时输入用户名 + 粘贴令牌什么都不用输
有效期自定，通常 90 天永久
抗网络波动走 443 端口，容易断走 22 端口，稳
配一次能做需要重新生成一直有效
令牌绝对不要贴进任何对话或截图

ghp_... 等于你账号的写权限。一旦泄露，立刻去 github.com/settings/tokens 删掉。 只在本机终端里粘贴（终端不回显）。

生成时必须勾选 repo 和 workflow 两项——少了 workflow 推不上去，会报 refusing to allow a Personal Access Token to create or update workflow。

配 SSH（推荐，一劳永逸）

# 1. 生成密钥（不需要联网）
ssh-keygen -t ed25519 -C "HanYi04" -f ~/.ssh/id_ed25519 -N ""

# 2. 打印公钥，整行复制
cat ~/.ssh/id_ed25519.pub

# 3. 粘贴到 github.com/settings/keys → New SSH key

# 4. 切换远程地址为 SSH
cd /mnt/Workbench/Midsite
git remote set-url origin git@github.com:HanYi04/HanYi04.github.io.git

# 5. 推送（第一次问 yes/no，输 yes）
git push -u origin main

配完以后再也不用输任何东西，也不会过期。

3.3 网络问题

这台机器到 GitHub 的 HTTPS 通道会被动态阻断——我实测过连续 8 次探测全部失败，过一会儿又恢复。表现是 git push 卡住或超时。

通道稳定性说明
github.com HTTPS (443)不稳，反复断被 TLS 层识别拦截
github.com SSH (22)从未失败测了 7 次全通
*.github.io很稳，约 900ms走 Fastly CDN，与主站不同线路

对策按顺序试：

  1. 装 Cloudflare WARP（已装，任务栏里那个）——warp-cli status 看到 Connected 就生效
  2. 改用 SSH（见上一节）——那条通道没被针对过
  3. 换网络——手机热点效果最明显
网站本身不受影响

被封的只是「你操作 GitHub」这条路。别人访问 hanyi04.github.io 走的是 Fastly CDN，一直很稳。所以推送失败不等于网站挂了。

3.4 验证部署

推完不等于生效，要等 GitHub Actions 构建完成。

1

打开仓库的 Actions 标签：

https://github.com/HanYi04/HanYi04.github.io/actions

最新那条如果显示绿色勾 Build and Deploy，就说明构建成功。黄色圆点是还在跑，红叉是有错误。

2

刷新网站，强制刷新绕过浏览器缓存：

Firefox 里按 Ctrl + Shift + R，或者访问 https://hanyi04.github.io/?v=2（加个参数）

改了没变化？按顺序排查
  1. Actions 里是绿色勾吗？如果是红叉，点进去看哪一步报错
  2. 是不是浏览器缓存？强制刷新试试
  3. GitHub Pages 有几十秒 CDN 缓存，再等一会儿
  4. 是不是推错分支了？确认在 main 分支上

五、环境准备（换机器才需要）

当前这台机器已经装好了：Ruby 在 ~/.local/ruby，Jekyll 4.4.1 已安装。以下内容仅在你换电脑时参考。

为什么装在 ~/.local

系统没有 sudo 权限（沙箱限制），所以全部用户级安装，不碰系统目录。

5.1 编译 Ruby

关键前提：缺 zlib 和 yaml 头文件

系统有 libssl-dev，但没有 zlib.h 和 yaml.h。不补上的话，编译出的 Ruby 无法使用 gem（RubyGems 依赖 zlib）。

mkdir -p /tmp/rbsrc && cd /tmp/rbsrc

# zlib
wget -q -O zlib-1.3.1.tar.gz https://github.com/madler/zlib/releases/download/v1.3.1/zlib-1.3.1.tar.gz
tar xzf zlib-1.3.1.tar.gz && cd zlib-1.3.1
./configure --prefix="$HOME/.local" && make -j"$(nproc)" && make install
cd ..

# libyaml
wget -q -O yaml-0.2.5.tar.gz https://github.com/yaml/libyaml/releases/download/0.2.5/yaml-0.2.5.tar.gz
tar xzf yaml-0.2.5.tar.gz && cd yaml-0.2.5
./configure --prefix="$HOME/.local" && make -j"$(nproc)" && make install
cd ..

# Ruby（20 核约 5-8 分钟）
wget -q -O ruby-3.3.6.tar.gz https://cache.ruby-lang.org/pub/ruby/3.3/ruby-3.3.6.tar.gz
tar xzf ruby-3.3.6.tar.gz && cd ruby-3.3.6
./configure --prefix="$HOME/.local/ruby" \
  --with-zlib-dir="$HOME/.local" \
  --with-libyaml-dir="$HOME/.local" \
  --disable-install-doc --without-gmp --without-readline \
  CPPFLAGS="-I$HOME/.local/include" LDFLAGS="-L$HOME/.local/lib"
make -j"$(nproc)" && make install

验证三个关键扩展：

~/.local/ruby/bin/ruby -e 'require "zlib"; require "yaml"; require "openssl"; puts "全部可用"'

5.2 安装 Jekyll

cd /mnt/Workbench/Midsite
export PATH="$HOME/.local/ruby/bin:$PATH"
bundle install

会装 38 个 gem，包括 jekyll 4.4.1、sass-embedded、kramdown、jekyll-sitemap。

六、项目结构详解

Midsite/
├── _config.yml          站点配置：名字、邮箱、主题色、导航、上线日期
├── _pages/              四个页面
│   ├── home.md          首页
│   ├── files.md         下载页（点击直接下载）
│   ├── preview.md       预览页（点击进入查看器）
│   └── view.md          查看器页面
├── _includes/
│   ├── head.html        meta、字体、MathJax、深色模式
│   ├── header.html      导航栏（含中文名映射）
│   ├── footer.html      页脚（日期时间 + 上线天数）
│   └── file-list.html   文件列表组件，下载页和预览页共用
├── _layouts/            页面骨架：default / gridlay / homelay / page / post
├── _sass/
│   ├── base/_variables.scss    所有颜色和间距变量（改配色看这里）
│   ├── components/_files.scss  文件列表样式
│   ├── components/_viewer.scss 查看器样式
│   └── bootstrap/       Bootstrap 5.3.3 原版 SCSS（92 个文件）
├── assets/
│   ├── main.scss        → 编译成 /assets/main.css
│   ├── files/           ★ 你的资料放这里
│   ├── images/          图片
│   └── js/
│       ├── site.js      深色模式切换等
│       └── viewer.js    查看器的文件渲染逻辑
├── _archive/            已归档的旧页面（Jekyll 不处理，可随时恢复）
├── .github/workflows/
│   └── deploy.yml       GitHub Actions 自动部署配置
├── serve.sh             本地预览
├── push.sh              自动重试推送
└── README.md            简要说明
下划线开头的目录不会被直接发布

_pages、_includes、_sass、_layouts、_archive 都是 Jekyll 的处理对象或忽略目录，不会原样出现在成品里。只有 assets/ 下的文件才会被直接复制发布。

文件列表是怎么自动生成的

_includes/file-list.html 的核心只有一行 Liquid：

{% raw %}{% assign all_files = site.static_files | where_exp: "f", "f.path contains '/assets/files/'" | sort: "modified_time" | reverse %}{% endraw %}

意思是：扫描所有静态文件，挑出路径里带 /assets/files/ 的，按修改时间倒序排。所以你把文件放进那个目录，构建时自动就被收录了。

八、容量与文件策略

项目限制说明
网页上传单文件 25MB通过 GitHub 网页拖拽
git push单文件 100MB（硬限）50MB 开始告警
仓库总量建议 <1GB，硬限 5GB超 1GB 后 clone 会变慢
Pages 站点发布产物 ≤1GB带宽软限 100GB/月
Releases 附件单文件 2GB不占仓库体积
Git LFS1GB 存储 + 1GB/月流量Pages 不支持 LFS，别用
Actions公开仓库无限免费你的仓库是 Public
大文件绝对不要 commit 进仓库

Git 是只增不减的：提交一个 500MB 文件，哪怕第二天删掉再提交，它仍然永久留在历史记录里，仓库体积一分不减。要清理得重写整个历史，非常麻烦。

超过 100MB 的文件放网盘，在首页贴个链接。

粗略的容量估算

内容能放多少
Markdown 文章（每篇 5KB）约 20 万篇（1GB 上限）
PDF 讲义（每份 5MB）约 200 份
照片（每张 3MB）约 330 张
视频基本放不了

九、踩坑清单

这些都是实际遇到并解决过的问题，记下来避免重复踩。

问题现象原因与解法
Markdown 里的 HTML 变代码块 页面上直接显示 <div class="..."> 源码 kramdown 把缩进 4 空格的 HTML 当代码块。用 {::nomarkdown}...{:/nomarkdown} 包起来
公式变纯文本 显示 [ E = mc^2 ] 用了 \(...\) 或 \[...\]，反斜杠被 Markdown 吃掉。改用 $...$ 和 $$...$$
改 url 时误改 baseurl 所有链接变成双份域名 s.replace('url: ""') 会匹配到 baseurl: "" 里的子串。要按行首精确匹配
页脚整块空白 版权行消失了 用 s.find() 截取时把后半段 HTML 一起删了。要用 rfind() 定位或整文件重写
CI 构建失败，找不到 SCSS Actions 报错 .gitignore 里的 vendor/ 把 _sass/bootstrap/vendor/ 也忽略了。改成 /vendor/（只忽略根目录）
推送被拒，提示 workflow refusing to allow a Personal Access Token... token 没勾 workflow 权限。重新生成时把 repo 和 workflow 都勾上
改了线上没变化 还是旧页面 浏览器缓存。按 Ctrl + Shift + R 强制刷新，或访问 域名/?v=2
导航看起来少一项 以为页面没生成 导航项由 _config.yml 的 nav_pages 决定，不在里面就不显示，哪怕页面文件存在
PDF 预览不出来 查看器区域空白 浏览器内置 PDF 阅读器的问题。已用 <object> 加了 fallback，实在不行点右上角「下载」
Word 预览一直转圈 预览区空白 走的是微软在线服务 view.officeapps.live.com，国内网络不稳定。下载后本地打开即可
